TOKENS WITHOUT LETTERS

Your tokenizer only sees letters.

A visual prototype for comparing tokenizer-like surface cost with spatial/color structure. Read it in three moves: colors replace decomposed writing units, every syllable-like group uses the same 3×3 capacity-based canvas, and the token-tax sketch asks whether structural grouping can flatten the unit-cost gap across writing systems.

Why 3×3?

Each block is a capacity-based syllable canvas. The grid is not just a layout normalization trick; it is the visual unit that lets the demo compare how different writing systems package sound-like structure.

English basisEnglish syllables are often described with an onset–nucleus–coda structure. Complex syllables can contain several consonants around one vowel nucleus, roughly captured by a heavy template like (C)^3 V (C)^4, as in strengths. A 9-slot grid is large enough for most syllable-like Latin groups while keeping one visual canvas.
Korean basisHangul syllables are already spatial blocks made from jamo, the alphabet-like pieces inside Korean syllables. For example, 국 decomposes into ㄱ + ㅜ + ㄱ. The same 3×3 canvas lets Korean expose internal jamo instead of becoming one opaque character.
What it does not claimThe grid is not saying every language naturally has 9-part syllables. It is a fixed, capacity-based visual unit: English fills it with letters from a syllable-like group, Korean fills it with jamo, and empty cells remain visible as density information.

Token tax flattening sketch

The fairness issue is not that Korean has more visible letters. The issue is that a surface-trained tokenizer can spend more units on Korean than on a comparable English sentence. This panel shows the intended before/after: baseline tokenizer-like units first, then Token Vision’s 3×3 structure groups. The important number is whether the English/Korean gap gets smaller.

Latin-script family sketch

Parallel phrases give the color texture more room to show repeated letter patterns, chunk rhythm, and family-adjacent similarities. This panel is the visual apparatus: it does not use language-family labels to build the representation.

Unsupervised structural similarity

This turns the Latin-family sketch into a small measurable check. The representation is computed without family labels, then the labels are shown afterward to see whether Romance/Germanic-adjacent examples cluster in a plausible way. It is a v0 sanity check, not a genealogy classifier.
